# OLED 状态屏

网表接线：OLED1.1/GND、OLED1.2/3V3、OLED1.3/SCL/GPIO16、OLED1.4/SDA/GPIO15。
默认按常见的 **SSD1306、128×64、四针 I2C OLED** 驱动。网表未注明控制芯片，具体型号仍需以实物为准。
驱动使用 [U8g2](https://github.com/olikraus/u8g2)，版本固定为 2.36.18。

## 显示内容

![OLED 帧缓冲预览：待机、按下 KEY1、录音](oled-layout-preview.png)

预览复用固件的绘制代码和 U8g2 字库，以整数倍放大像素，并非开发板实拍。

示意排布如下，三个快捷键从左到右对应实体 KEY1～KEY3，按下时整块反白：

```text
ibook              蓝牙 已连接
────────────────────────────
╭────────╮╭────────╮╭────────╮
│ 1 复制 ││ 2 粘贴 ││ 3 撤销 │
│ Ctrl+C ││ Ctrl+V ││ Ctrl+Z │
╰────────╯╰────────╯╰────────╯
────────────────────────────
[4] 录音 2.4s
    ███████···················
```

顶部占 14 像素，快捷键区占第 16～43 行，语音区占第 47～63 行。
组合键与中文名称分两行；KEY4 使用独立编号框，按住或录音时反白。
录音/发送进度独占底部 108 像素宽的区域，不再和提示文字争用同一行。

- 顶部：未连接、配对中、已连接。已连接表示键盘报告就绪。
- 旋钮操作：品牌名右侧临时显示上三角 ▲、下三角 ▼ 或回车箭头与“确定”，一秒后图标消失；不覆盖蓝牙和录音状态。
- KEY1～KEY3：编号、中文名称和当前配置的组合键，按下整块反白、松开恢复。
- KEY4：未订阅语音时提示“先启动PC”；就绪后提示“按住录音”。
- 录音时：显示已录秒数和相对于最长 10 秒的进度；发送时显示已确认帧的百分比。
- 发送完成时：显示“发送完成”。电脑的语音识别结果没有回传给固件，因此这里不显示识别结果。
- 异常时：提示检查麦克风、传输超时、录音太短等。

快捷键名称与组合键统一在 `include/shortcut_config.h` 的 `KEYS` 表中配置。
绘制代码在 `src/display_renderer.cpp`，屏幕任务与 I2C 初始化在 `src/status_display.cpp`。
屏幕使用消抖后的实体按钮状态；不会为显示效果额外发送快捷键或控制录音。

## 型号、地址与亮度

配置在 `include/display_config.h`：

| 配置 | 默认值 | 用途 |
| --- | --- | --- |
| `OLED_USE_SH1106` | `0` | SSD1306；SH1106 屏改为 `1` 后重新编译 |
| `DisplayConfig::ADDRESS` | `0` | 自动尝试 0x3C、0x3D；也可填写明确的 7 位地址 |
| `DisplayConfig::CONTRAST` | `128` | 亮度，范围 0～255 |
| `DisplayConfig::BUS_HZ` | `400000` | 硬件 I2C 频率；较长接线不稳定时可尝试 100000 |
| `DisplayConfig::UPDATE_MS` | `100` | 主循环发送显示快照的间隔，单位 ms |

当前排版只适用于 128×64。128×32 屏需要调整布局和驱动，不能只改地址。
I2C 扫描只确认地址有应答，不能据此区分 SSD1306 和 SH1106。

## 编译与烧录

```powershell
pio run
pio run -t upload
```

继续使用 USB 诊断环境时：

```powershell
pio run -e esp32-s3-usb-debug
pio run -e esp32-s3-usb-debug -t upload --upload-port COM24
```

端口以实际设备为准。成功初始化后，日志类似：

```text
[OLED] SSD1306 128x64 at 0x3C; SDA=15 SCL=16.
```

## 不亮时怎么查

1. 确认 VCC 为 3.3V、GND 已共地，SDA 接 GPIO15、SCL 接 GPIO16，注意屏幕插针顺序。
2. 日志显示 `Not found at 0x3C/0x3D` 时，检查供电、连线和模块 I2C 上拉；后台每 5 秒重试。
3. 地址能找到但黑屏、画面偏移或缺列时，核实是否为 SH1106，并切换对应配置。
4. 屏幕刷新在独立任务中；缺少屏幕、I2C 超时或显示任务申请失败不会阻塞键盘和录音。

主循环只投递最新状态，不等待屏幕。屏幕任务独占 Wire/U8g2，仅当画面内容变化时刷屏；
录音状态快照不会跨任务直接读取状态机的普通变量。

## 初始化后立即失联

若先打印屏幕地址，接着出现 `Disconnected; searching again`，不能直接据此判定屏幕损坏。
本项目在扫描后调用 `Wire.end()`，再由 U8g2 初始化屏幕：U8g2 会先设置 GPIO 方向，
Arduino-ESP32 2.x 的 `Wire.begin()` 在总线已启动时又会跳过初始化；不先结束扫描总线会使引脚配置冲突。
该顺序同样适用于后台重新连接。

## 四个按钮的硬件诊断

USB 诊断版本打开监视器后输入 `d`，启用按钮变化日志；再次输入 `d` 关闭。
输入 `s` 可随时打印一次当前状态。原始位 `K1`～`K4` 中，`1` 为按下，`0` 为松开。
`debounced` 是前三个快捷键消抖后的位图，KEY4 的状态由语音模块独立处理。

- 按下后对应原始位始终不变：检查该 GPIO 到按键、按键到 GND 的接线和焊接。
- `BLE ready=0`：键盘报告尚未就绪，不能仅凭蓝牙“已配对”判断可发送快捷键。
- `voice subscribed=0`：电脑语音接收程序尚未订阅音频，KEY4 会拒绝录音并提示先启动 PC。
- 原始位、消抖位正常且 `BLE ready=1` 时，在记事本中先选中文字测试复制，再把光标移到末尾测试粘贴。

默认不开启按钮日志；读取状态本身不会发送真实快捷键。
